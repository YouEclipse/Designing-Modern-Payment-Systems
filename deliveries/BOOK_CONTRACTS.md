# 《设计现代支付系统》全书交付合同

> 性质：写作与配套 Go 系统的执行地图，不是章节正文，也不代表下列能力已经实现。
> 覆盖范围：第 4～22 章与附录 A～C；第 1～3 章是前置基线。目录编号保持不变。

## 0. 合同状态

本文件描述“应该交付什么”，默认状态是 `target_contract`，不是完成声明。每项能力只能按以下三种状态解释：

| 状态 | 可声称的范围 | 所需证据 |
| --- | --- | --- |
| `implemented` | 当前 `payments` 代码中存在并由实际测试覆盖的窄能力 | 对应交付清单的“主张→代码→测试”映射、固定实现提交与该提交的绿色持续集成任务 |
| `teaching_model` | 正文中可编译、可反例验证的 Go 模型 | 本书验证器与专属测试；不能由此推导服务、数据库、工作进程或真实支付服务商运行能力已经实现 |
| `target_contract` | 未来实现必须满足的权威边界、状态与失败语义 | 设计说明和失败测试计划；不代表已经具备运行能力 |

章节或附录的当前状态以各自交付记录为准；同一章可以同时包含已实现基线、教学模型和目标合同。下文“窄而完整的 Go 纵向增量”是目标描述，只有交付记录明确标为 `implemented` 且固定代码证据齐全后，才能改称当前实现。

## 1. 使用方式与全书范围护栏

每章围绕一条“能从 API 进入、穿过领域模型与持久化、在失败条件下仍可验证”的窄纵向切片组织目标合同。章节正文遵循“问题 → 简单设计 → 规模化问题 → 生产级设计 → 故障模式 → 权衡 → 小结”；需要配套运行实现的能力必须先发布代码，待持续集成全部通过后，再把固定提交值写入对应交付记录。

以下两项不是独立章节：

- **服务商适配器与服务商连接身份**并入第 3 章；第 6 章只扩展适配器对外发布的版本化能力事实与准入筛选，不另增“适配器章”。
- **风险感知路由**并入第 9 章服务商评分；欺诈引擎继续拥有风险判断，路由服务只消费带版本、时效和原因码的风险决策。

全书共同红线：

1. 授权、请款、结算是不同资金阶段；`SALE` 只是当前自动请款流程中的服务商原生操作，不能被写成通用授权。
2. 请款、撤销、退款始终绑定原服务商连接和交易引用，不重新路由。
3. 超时、断连、响应丢失和含糊的 5xx 响应先进入 `UNKNOWN`；同一逻辑资金操作只能复用原连接、请求载荷、服务商幂等键与资金操作编号。
4. 准入筛选的硬约束先于规则偏好和评分；分数、实验或模型都不能复活不合格候选通道。
5. 路由服务生成可解释的路由决策；支付服务/支付编排器拥有支付意图、支付尝试、资金操作、幂等和资金状态迁移；服务商网关/适配器执行已经固定的连接。
6. 所有迟到资金证据都追加保存，不能采用“后写覆盖前写”；重复或更弱且不冲突的观察按领域规则归约为无操作，只有不相容、身份冲突或无法安全归属的证据才进入 `review_required`。
7. 支付凭证令牌化不会自动把系统移出 PCI DSS 范围；PAN、CVV/SAD、服务商密钥不进入路由上下文、路由决策、日志、追踪、指标或事件。

## 2. 当前代码基线与第 3 章前置合同

当前实现的审计锚点如下；后续章节必须在这些真实边界上演进，不另造一套示例系统。

| 当前事实 | 工程锚点 | 后续约束 |
| --- | --- | --- |
| 支付服务是支付聚合与商户幂等的唯一写入者，并原子固定 v3 上下文/决策/风险/优化证据与不可续期的执行期限 | `services/payment/internal/app/service.go`、`services/payment/internal/postgres/{routing_evidence,recovery}.go`、迁移 `005`/`006` | 支付意图/支付尝试/资金操作的迁移仍在支付服务事务内完成；首次执行权限和已派发操作的恢复不得混为一谈 |
| 路由服务 v3 已按精确连接与修订运行“能力 → 规则 → 风险 → 成本/观察性表现 → 整数评分”的约束流水线 | `services/router/internal/{capability,decision,cost,performance,scoring}`、`contracts/internal/router-api.openapi.yaml` | 基于夹具的本地证据不得冒充真实 PSP 报价、因果成功率、动态健康度或欺诈引擎 |
| 服务商网关以不可变连接修订执行服务商资金操作，使用派发比较并交换、结构化无副作用证明与追加式观察账本收敛不确定结果 | `services/provider-gateway/internal/gateway/`、迁移 `0003`～`0005`、`contracts/internal/provider-gateway-api.openapi.yaml` | 适配器不能暗中改路；查询/原键重提必须使用原资金操作、连接、幂等键与请求载荷，普通 404 不授权资金重提 |
| 当前资金切片仅支持令牌化银行卡、自动请款和单个 `SALE` 操作 | `contracts/public/payment-api.openapi.yaml`、`README.md` | 手动请款、撤销、退款只有在相应章节明确实现后才能宣称支持 |
| PostgreSQL 已有商户幂等、发件箱/收件箱、引用唯一性、隔离区、不可重置的恢复预算/截止时间/租约、路由快照与时钟见证 | `services/payment/internal/postgres/`、`docs/runbooks/` | Redis、消息代理或新服务只有在章节压力真实要求时才引入；它们不能替代数据库事实，生产升级必须执行 006 预检 |
| 持续集成端到端测试证明批准、拒绝、风险阻断/无候选通道的零资金路径、响应丢失→`UNKNOWN`→同一资金操作收敛，以及并发幂等只有一条资金路径 | `test/e2e/payment_flow_test.go`、`.github/workflows/ci.yml` | 后续测试必须保留这些回归；当前模拟器证据不等于真实 PSP 认证 |

第 3 章结束时必须提供后续章节可依赖的最小前置：

- `RouteCandidateID` 稳定标识“服务商 + 商户账户 + 连接器 + 执行区域”；路由响应、支付尝试、服务商操作、网关请求与数据库都保存该身份或不可变快照。
- 路由服务只返回决策；支付服务固定所选连接后创建支付尝试与操作；网关根据连接找到适配器与凭证，不能仅按服务商名称临时选择账户或区域。
- 适配器的执行契约至少覆盖当前 `ExecuteSale` 与 `QueryOperation`；授权、请款、撤销和退款仅作为边界说明，不在第 3 章虚假实现。
- 第 3 章定义连接身份和执行边界，第 6 章才定义完整能力目录、三值准入筛选与新鲜度策略。

## 3. 逐章可执行合同

### 第 4 章 构建路由上下文

| 合同项 | 内容 |
| --- | --- |
| 核心命题 | 路由服务的决定只能和输入快照一样可靠；路由上下文必须版本化、来源明确、可校验且不携带支付凭证。 |
| 简单系统 | 支付服务直接把不断增长的参数列表传给 `route(...)`，路由服务猜测缺失字段和默认值。 |
| 规模/失败压力 | 多上游字段同名异义、金额单位漂移、缺失值被当成零、实时信号过期、决策无法复现，以及令牌或 PAN 被误传到路由服务。 |
| 自然推导组件或不变量 | 支付服务边界内的 `ContextBuilder`；`RoutingContextV1` 按商户、交易、支付方式、风险引用与运行时引用分组；每个派生或实时字段带来源、`observed_at` 与版本。上下文中只允许非敏感类别与派生属性。 |
| 明确留给后章 | 规则求值留第 5 章；完整能力留第 6 章；风险决策语义留第 9 章；不可变决策存储留第 14 章；数据驻留留第 19 章。 |
| 窄而完整的 Go 纵向增量 | 新增 `services/payment/internal/routingcontext` 的构建器与验证器；扩展 `clients.RoutingRequest`、路由服务 HTTP 数据传输对象与 OpenAPI，携带 `schema_version`、商户国家、金额与币种、支付方式类别、请款模式和带时效的非敏感派生字段。支付服务从支付意图与商户配置构建一次快照，路由服务严格解码并拒绝未知或不兼容模式。 |
| 证明性失败测试 | 构造包含 `payment_method_token`、`pan` 或 `cvv` 的路由请求载荷，必须在契约或 HTTP 层失败；缺失金额币种语义或传入过期必需引用时不得默默选路；同一规范化上下文的序列化摘要必须稳定。 |
| 官方一手资料类别 | PCI SSC 的 CHD/SAD 与令牌化指南；ISO 4217 货币小数位资料；目标服务商与支付方式的官方字段和认证要求。 |
| 依赖前章 | 第 1 章金额与生命周期术语；第 3 章路由 API、连接身份和敏感数据边界。 |
| 图形锚点 | Mermaid 流程图：五类上游→上下文构建器→路由服务；表格：字段、来源、时效、缺失策略、敏感级别；Ian 插图可用“把杂乱包裹过安检再装入透明箱”的隐喻，不画字段精确关系。 |

### 第 5 章 基于规则的路由

| 合同项 | 内容 |
| --- | --- |
| 核心命题 | 路由规则是不可变、确定、可解释的策略制品；它表达显式业务意图，但不能替代服务商准入验证。 |
| 简单系统 | 在路由服务的 Go 代码中不断增加按商户、国家与币种判断的 `if/else` 和紧急开关。 |
| 规模/失败压力 | 例外相互覆盖、优先级不明、同一规则在实例间漂移、紧急改路无法审计，以及强制指向不存在或不合格的连接。 |
| 自然推导组件或不变量 | `RuleSet{Version, EffectiveAt, Rules}`、确定性求值器、稳定优先级与冲突语义；求值输出规则命中、动作与原因，而不是直接执行服务商调用。已发布制品不可变。 |
| 明确留给后章 | 完整能力与“强制规则也不能越过准入筛选”的闭环留第 6 章；权重评分留第 9 章；审批、灰度、分发和回滚控制平面留第 20 章。 |
| 窄而完整的 Go 纵向增量 | 在 `services/router/internal/rules` 实现受限 AST（等值、集合、范围）及 `prefer/exclude/force/split` 的确定性求值；路由服务启动时从严格 JSON 制品加载一个不可变版本，决策返回 `rule_set_version` 和命中原因。现有静态服务商顺序成为无规则命中时的安全默认。 |
| 证明性失败测试 | 两条作用域和优先级相同且动作冲突的规则使制品校验失败；规则文件顺序变化不改变决定；调用方试图在请求中注入规则或版本必须被 OpenAPI 与 HTTP 严格解码器拒绝。 |
| 官方一手资料类别 | JSON Schema 官方规范；Go `encoding/json` 与排序和时间官方文档；商户与服务商合同中可被编码为策略的原始条款。 |
| 依赖前章 | 第 4 章稳定上下文字段与缺失语义；第 3 章候选通道与连接身份。 |
| 图形锚点 | Mermaid 时序图：加载制品→校验→原子启用→求值；表格：动作、可覆盖范围、冲突规则、原因码；Ian 插图可用“贴满便签的岔路口失控后换成编号信号灯”。 |

### 第 6 章 服务商准入筛选

| 合同项 | 内容 |
| --- | --- |
| 核心命题 | 先证明一条具体服务商连接能合法且技术上处理当前操作，再谈偏好；准入筛选是带证据的硬过滤，不是分数。 |
| 简单系统 | 把 PSP 名称当候选通道，并默认一家 PSP 的所有账户、区域、操作和支付方式能力相同。 |
| 规模/失败压力 | 同一 PSP 多个商户账户和连接器能力不同；币种、国家、请款模式、3DS、令牌可移植性或合同状态不匹配；能力数据缺失或过期却被当成支持。 |
| 自然推导组件或不变量 | 适配器发布规范化 `CapabilityDescriptor`；路由服务拥有版本化 `CapabilityCatalog` 视图；`EligibilityResult` 为 `eligible/ineligible/unknown` 并带稳定原因码。`unknown` 不默认升级为 `eligible`。 |
| 明确留给后章 | 费用留第 7 章；经验成功率留第 8 章；风险护栏留第 9 章；动态健康度只在第 13 章进入准入筛选；配置审批留第 20 章。服务商适配器的执行边界已在第 3 章完成，不另开新章。 |
| 窄而完整的 Go 纵向增量 | 在第 3 章已贯穿的 `RouteCandidate/ProviderConnection` 身份上，新增 `services/router/internal/capability` 目录与过滤器，支持币种、国家、支付方式、操作、请款模式、启用状态和生效区间；路由合同返回目录版本和三值过滤证据。支付服务与网关继续使用第 3 章已经固定的连接，不在本章重新设计身份。 |
| 证明性失败测试 | 配置同一 PSP 的两个连接，其中只有一个支持 USD 自动请款；即使规则强烈偏好另一个，也只能选择合格连接。过期或字段未知的能力必须产生 `capability_unknown/stale`，不得调用网关。 |
| 官方一手资料类别 | 各服务商官方 API、能力矩阵、API 版本、幂等和回调文档；卡组织与本地支付方式的官方操作和认证规则；商户账户合同约束。 |
| 依赖前章 | 第 3 章连接与适配器边界；第 4 章操作、请款与上下文；第 5 章只产生策略偏好。 |
| 图形锚点 | Mermaid 流程图：能力目录→逐项硬过滤→合格集合→策略顺序；表格：候选通道身份各字段与所有者、三值结果和降级动作；Ian 插图可用“同品牌多扇门，钥匙、地区和营业牌照各不相同”。 |

### 第 7 章 成本感知路由

| 合同项 | 内容 |
| --- | --- |
| 核心命题 | 在线路由比较的是可解释的预期成本，而不是一项标价；所有货币和费率计算必须确定、可追溯且不使用浮点数。 |
| 简单系统 | 给每家服务商配置一个百分比费率，选择百分比最低者。 |
| 规模/失败压力 | 固定费、跨境费、FX、币种换算和失败尝试改变真实成本；费率有效期或合同版本错配；最低支付尝试成本不等于最低成功支付成本。 |
| 自然推导组件或不变量 | 版本化 `FeeSchedule`、整数微单位或定点数 `CostEstimate`、逐项 `CostBreakdown` 与缺失或过期标志；只对第 6 章准入筛选后的候选通道估算。预期成本与实际成本永久分列。 |
| 明确留给后章 | 成功概率留第 8 章；多目标组合留第 9 章；账单、阶梯价最终校准和实际成本留第 18 章；配置治理留第 20 章。 |
| 窄而完整的 Go 纵向增量 | 新增 `services/router/internal/cost`，支持固定费、基点费率与显式跨境附加费的一条定点数估算链；从不可变制品加载 `fee_schedule_version`，决策返回分解与币种。缺少可靠 FX 或费率时由策略明确拒绝或退出成本比较，不能当作零成本。 |
| 证明性失败测试 | 低百分比但高固定费的候选通道在小额交易中不应被误选；费率边界 `effective_from/to` 交界结果确定；大金额乘法无溢出，缺失 FX 不得产生零成本或 NaN。 |
| 官方一手资料类别 | 服务商与收单机构官方费率及账单字段；卡组织官方费用说明；ISO 4217 与受认可 FX 基准发布方的原始资料。 |
| 依赖前章 | 第 4 章金额、币种与国家；第 6 章准入筛选后的候选通道与商户账户和区域。 |
| 图形锚点 | Mermaid 流程图：合格集合→费率查询→成本分解；表格：费用项、触发条件、单位、版本、在线是否可知；Ian 插图可用“便宜门票后面拖着多张隐藏小票”。 |

### 第 8 章 成功率路由

| 合同项 | 内容 |
| --- | --- |
| 核心命题 | 可用于单笔路由的是带样本量、窗口、置信度和回退层级的条件成功率估计，不是服务商总榜。 |
| 简单系统 | 按服务商汇总最近一天授权率，选择最高者。 |
| 规模/失败压力 | 流量构成和历史路由造成选择偏差；高维分桶稀疏、冷启动、延迟事件、低流量 100% 样本和时间漂移让排行抖动。 |
| 自然推导组件或不变量 | 不可变 `PerformanceSnapshot`、分层分段键、样本量、窗口、`observed_at`、贝叶斯平滑或显式收缩，以及从细到粗的回退链。估计值必须携带证据，不能伪装成因果效果。 |
| 明确留给后章 | 成本与成功率综合评分留第 9 章；健康度的分钟级运行信号留第 13 章；指标生产与 SLO 留第 15 章；因果实验留第 16 章；最终结果校正留第 17、18 章；机器学习反事实问题留第 21 章。 |

| 配置包 | 路由配置平台 | 路由服务原子加载并确认；其他服务引用摘要 | 第 20 章 | 完整配置包原子切换、保留最近一个已知可用版本、作者与审批者分离、可回滚 |
| 模型制品 | 训练系统与模型注册表发布；配置平台审批；路由服务只读提供服务 | 回放与实验负责评估；决策记录版本 | 第 21 章 | 不能越过护栏；不支持、`NaN` 或超时时回退；需记录选择概率和支持度 |
| 账本 | 外部账本与财务系统 | 支付与结算服务可发送事实，路由服务只引用 | 第 1、17、18 章边界 | 决策存储、对账或结算投影都不能冒充会计账本 |

## 6. 批次发布顺序

“批次”是依赖波次，不是把多章压成一次大提交。批次内部仍按章节逐一执行：**代码仓增量与失败测试 → 全部代码门禁/CI → 固定实现 SHA → 完整正文、Mermaid/表格/必要 Ian 图 → 交付清单 → 书仓检查/推送**。

| 波次 | 章节 | 代码侧结束门禁 | 为什么必须按此顺序 |
| --- | --- | --- | --- |
| 0. 前置基线 | 第 1～3 章 | 当前自动请款纵向链路持续全绿；精确候选通道与连接从路由服务贯穿支付服务、网关和数据库；适配器只执行不路由 | 后续所有能力、幂等键作用域、健康度和归因都依赖可执行连接，不可继续使用模糊的服务商品牌字符串 |
| 1. 决策输入与硬边界 | 第 4～6 章 | 上下文无敏感凭证且严格版本化；规则制品确定；能力三值过滤和两个同 PSP 连接的端到端测试 | 先固定输入、策略语义和合法集合，才允许引入优化信号 |
| 2. 可解释优化 | 第 7～9 章 | 定点成本、稳健成功率、风险护栏与稳定评分明细；准入筛选优先于评分的失败测试 | 成本、成功率和风险在同一流水线收束，防止三章各自做选择器 |
| 3. 单笔可靠性 | 第 10～12 章 | `UNKNOWN` 崩溃恢复、三层并发幂等、严格无副作用的后备切换端到端测试；单路径回归持续通过 | 先证明原操作安全恢复，再允许创建第二次支付尝试 |
| 4. 跨交易可靠性与证据 | 第 13～16 章 | 局部断路器与舱壁、只追加决策投影、有限基数遥测、影子运行无副作用与稳定分桶 | 健康度、审计和观测建立后，才有资格运行真钱策略实验 |
| 5. 事实与经济闭环 | 第 17～18 章 | 带检查点的对账、冲突复核、结算行幂等匹配和预期成本与实际成本对比 | 先校正支付事实，再用其计算实际成本，避免反馈污染 |
| 6. 全球执行与治理 | 第 19～20 章 | 两区域隔离与脑裂测试；配置双人审批、配置包原子切换、最近一个已知可用版本与回滚 | 多区域明确本地与全局状态后，控制平面才能正确发布到各区域 |
| 7. 可选智能化 | 第 21 章 | OPE 支持度校验、影子与挑战者模式、模型故障回退、护栏不可绕过 | 只有决策、实验、配置和实际结果都存在时，模型比较才有证据基础 |
| 8. 综合收束 | 第 22 章、附录 A～C、术语表最终校正 | 四条系统故障旅程、竞态检测、静态检查、契约测试、集成测试、Compose 端到端测试，以及容量与上线报告；全部术语、状态和链接一致 | 最后只组合和审计已有机制，不在案例章或附录偷偷引入新核心能力 |

每一波次都保留上一波次回归；尤其是商户幂等、`UNKNOWN` 单资金路径、冲突 `review_required`、生产环境禁用模拟器且默认拒绝，以及 PAN/CVV/SAD 禁止项。若本机没有真实 PostgreSQL/Compose 条件，不能省略测试，只能把最终门禁交给最新 GitHub Actions 并等待全绿。

## 7. 范围与重复自检

### 7.1 唯一主责检查

- 路由上下文只在第 4 章首次设计；第 14 章只保存摘要和版本证据。
- 规则求值只在第 5 章；能力与准入筛选只在第 6 章；控制平面生命周期只在第 20 章。
- 成本估计只在第 7 章；成功率估计只在第 8 章；风险与多目标选择只在第 9 章；第 21 章模型只能实现同一评分器接口。
- 重试与 `UNKNOWN`（第 10 章）、身份与幂等（第 11 章）、新支付尝试的后备切换（第 12 章）、面向后续请求的健康度（第 13 章）是四种不同机制。
- 决策证据（第 14 章）、测量（第 15 章）、因果实验（第 16 章）、事实校正（第 17 章）和经济归因（第 18 章）不能互相代替。
- 多区域所有权（第 19 章）与配置分发治理（第 20 章）分开；DNS、缓存或配置版本都不能替代隔离机制。
- 服务商适配器不新增章：第 3 章定义执行边界，第 6 章定义能力发布。风险感知路由不新增章：全部收束在第 9 章。

### 7.2 不提前透支检查

- 第 4～8 章只产生带类型的输入和特征，不提前实现决策存储、实验或机器学习。
- 第 10 章不创建新支付尝试；第 11 章不声称跨 PSP 幂等键去重；第 12 章不把 `UNKNOWN` 当作后备切换条件。
- 第 13 章只处理技术健康度，不用授权率触发断路器；第 15 章的指标不自动修改资金状态。
- 第 17 章自动修复只走领域状态机；第 18 章不创建账本；第 20 章不允许在线实例拼接半套制品。
- 第 21 章没有可靠选择概率和支持度时，不得宣称因果提升；第 22 章的 10 万 TPS 是目标约束，只有实测证据才能成为容量结论。
- 附录只统一参考与门禁，不在目录末尾偷偷实现正文没有解释的新支付能力。

### 7.3 每章进入正文前的最小验收

1. 对照本文件写一页章节契约，并把“留给后章”原样转成交付清单的未实现范围。
2. 在代码中先补失败测试，再实现唯一纵向增量；Go 示例必须来自或可映射到真实包/API。
3. 检查本章术语在上表只有一个权威所有者，状态变化只由所有者执行。
4. 在线核验服务商、标准、法规和合规陈述，只使用对应官方或原始资料，并把链接贴近主张。
5. 选择最小信息图：精确关系优先 Mermaid/表格；Ian 图只承担直觉和节奏，不能替代状态机、时序或数据表。
6. 更新术语表、OpenAPI、README、架构 ADR 和交付清单；所有能力声明必须区分教学模拟器、可运行支付核心、PSP 沙箱与生产系统。
